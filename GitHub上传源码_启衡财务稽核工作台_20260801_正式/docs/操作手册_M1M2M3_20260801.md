# 启衡财务稽核工作台（M1–M3）操作手册

适用对象：财务复核人员、项目验收人员。  
本版范围：M1 登录连接、M2 费用报销审核与安全写回、M3 发票台账稽核；不包含 M4。

## 一、首次启动

1. 先启动导师提供的 ERP/API 环境。ERP 门户通常为 `http://127.0.0.1:8080`，工作台连接的是 API，例如 `http://127.0.0.1:8081`。
2. 打开 EXE，填写 API 地址和在 ERP「开发者中心」创建的 API Key。
3. 点击“登录并进入工作台”。Key 不随 EXE 分发、不预置到新电脑，也不显示在主页。

建议申请的最小权限：

- `expense:read`、`approval:read`、`attachment:read`：M2 读取单据、审批和原始票据；
- `invoice:read`、`master-data:read`：M2 台账核验与 M3 扫描；
- `expense:review`：仅在人工确认后写回审核意见。

## 二、M2：费用管理 / 费用报销单

### 1. 拉取和查看

- 点击“刷新待审单据”，系统从当前 API 拉取 `PENDING` 单据；不把旧缓存当作当前队列。
- 选择一张单据后，系统重新读取完整单据、审批/特批、费用行、附件、关联台账，并生成本次建议。
- 中间区域选择费用行，右侧切换对应原始票据；可上一张、下一张、点击放大。

### 2. 阅读 AI 建议

每项建议应包含问题、制度依据、原始证据、实际值、正确值/口径、影响和下一步。证据优先级为：原始票据 > 人工确认值 > ERP 发票台账 > ERP 字段 > OCR > 模型建议。

电子客票、火车票、机票等通常没有增值税发票购买方字段：

- 不会因 OCR 空白自动通过；
- 必须核对关联 ERP 台账的购买方和税号；
- 台账缺失或不一致时进入“待人工复核/二次复审”；
- 财务人工确认台账错误时，系统给出建议驳回及完整证据。

### 3. 人工确认与校准

- “确认通过”“确认驳回”“转人工复核/补充材料”均需填写理由。
- OCR 字段纠正：打开“人工校准与样本”，选择具体费用行。发票填写原票实际值；电子客票填写 ERP 台账实际值。金额仅在需要纠正金额时填写。
- 点击“保存校准并重新判责本单”后，系统将保存本地人工确认样本，并重新读取本单所有证据后完整重判。
- 校准不会自动修改 ERP、全局规则或 OCR 模型。制度/白名单/特批建议需要管理员审核、版本化后才可发布。

### 4. 批量写回 ERP

流程：人工确认 → 写回前预检 → 确认批量写回。

- 仅 ERP 当前没有任何审核意见的单据允许写回。
- 已有相同或不同意见都会保留在 ERP，不被覆盖；系统标记后由财务在 ERP 中处理。
- 点击确认写回前，系统会再次读取既有意见，防止并发情况下误写。
- 写回仅创建审核意见，不改变单据状态、不付款、不删除记录。

## 三、M3：发票与往来 / 发票台账稽核

1. 点击“读取全量发票，开始稽核”。系统只读分页拉取发票台账和供应商主数据。
2. 页面展示票面待核查、重复发票、主数据待完善等异常；每项可查看实际值、制度口径、稽核依据与建议动作。
3. 为异常设置负责人、处理状态、备注或导出清单。

M3 不调用 ERP 回写接口。税率、抬头/税号、重复票均为稽核任务：财务需按合同、业务实质、红冲/重开、冲销/调整等真实流程闭环。

## 四、常见问题

| 现象 | 处理方法 |
|---|---|
| 登录提示连接失败 | 确认 Docker/ERP 已启动；API 使用 `127.0.0.1:8081` 或 `localhost:8081`，不要填 ERP 门户 `:8080`。 |
| HTTP 401 invalid_api_key | Key 无效、已吊销或来自另一套环境；到当前 ERP 开发者中心重新创建。 |
| HTTP 403 insufficient_scope | 根据提示补充最小权限；只做读操作无需申请写回权限。 |
| 附件无法读取 | 不直接通过；查看原始文件，必要时转人工复核/补充材料。 |
| 车票 OCR 没有购买方 | 这是常见情况；核对关联 ERP 台账，不要把 OCR 空白当作合规。 |
| 校准后建议没有变化 | 确认填写的是“实际值”而非期望值，填写校准依据，并点击保存后的整单重判；再次单审/批审也会保留已确认字段。 |
| 写回显示意见冲突 | ERP 已有意见，系统按安全边界跳过；请在 ERP 中核对并由财务处理。 |

## 五、数据与安全说明

- 原始票据仅下载到本机运行目录，用于本地 OCR、审计包和人工确认；不调用外部云模型。
- API Key 不写入交付包；请勿截图、邮件或提交到 Git 仓库。
- 本地历史缓存、人工样本和审计包均有时间/来源/规则版本属性，只作参考，不替代当前 API 拉取结果。
